# Проверка входящего номера через Asterisk с аудиофразой

## Разрешение и границы

Проверка настроек сама по себе не разрешает звонок. Нужны прямое поручение пользователя, целевой номер и согласованный источник. Если пользователь разрешил любой наш мобильный/технический источник, выбирай существующий подходящий маршрут и называй его. Не создавай постоянные маршруты, не перенастраивай сотрудников, транки, NAT/firewall и не применяй чужие накопленные изменения FreePBX ради теста.

По умолчанию выполняй один тест. При неопределённом результате сначала проверяй журналы, а не повторяй вызов. Этот навык не разрешает массовый обзвон или мониторинг со звонками.

## Аудиозапись

- Готовый файл: `../assets/crmcalls-test.wav` относительно этого справочника.
- Фраза: «Тестовый звонок crmcalls. Проверка входящей линии».
- Русский голос Microsoft Irina Desktop, WAV PCM, 8000 Гц, 16 бит, моно, около 5,9 секунды. Файл не содержит начальной паузы.
- Для новой фразы можно использовать установленный локальный русский TTS. Не заменяй согласованный текст произвольно. Сохраняй отдельный файл, проверяй его формат и продолжительность.
- Учти ранний ответ Манго: Asterisk может начать Playback раньше, чем сотрудник поднимет трубку. Для следующего теста подготовь вариант с начальной тишиной (например, 3–5 секунд) и сопоставь её с фактическим временем соединения. Пауза снижает риск обрезки, но не гарантирует полное прослушивание при любом ожидании.

## Подготовка

1. В живом Манго проверь номер → активная схема → точный сотрудник/добавочный, алгоритм и таймаут. Не полагайся на старые ID.
2. Проверь доступ к FreePBX/Asterisk. В среде Зари проверенный хост — `<SERVICE_HOST>`; браузерный вход не означает SSH-доступ. Если авторизация истекла, попроси войти, не проси пароль в чат.
3. Через штатный CLI прочитай `pjsip show registrations`, нужный endpoint и активные каналы. Выбирай действующий тестовый транк, разрешённый для нужного направления. Наличие регистрации не доказывает прохождение звонков.
4. Загрузи отдельную системную запись через FreePBX → Администратор → Записи в системе. Зафиксируй реальное имя файла и язык. Не делай Apply Config для всего сервера: в проверенном случае Playback работал после сохранения записи без применения накопленных правок.
5. До вызова сохрани цель, источник, путь аудио, точное время МСК и статус `pending`. Не помещай секреты в журнал.

## Один вызов и доказательства

Поддерживаемая команда CLI:

```text
channel originate PJSIP/<целевой-номер>@<проверенный-endpoint> application Playback <путь-без-расширения>
```

Выполняй только на согласованный номер и через проверенный исходящий endpoint. Такой прямой вызов не проходит правила исходящего маршрута FreePBX: его нельзя выдавать за проверку этих правил. Для проверки обычного маршрута нужен отдельно проверенный способ запуска через его контекст с правильным Caller ID.

В тесте 27.10.2026 использовались `MANGO_TEST` и `custom/crmcalls-test`, язык endpoint `ru`. Это исторический пример, не постоянные настройки. После ответа Asterisk запускает Playback; завершение аудио заканчивает тестовый канал.

Проверяй последовательно:

- Asterisk: целевой номер, имя канала, `answered`, `Playing`, ошибки отсутствия файла/кодека. Пустой ответ CLI сам по себе не является успехом.
- Манго: исходящий технический вызов и входящий на целевой номер, время, точный получатель, статус «Принял вызов» / «Пропустил вызов», ожидание, разговор и причина завершения. Совпадение близкого времени само по себе не доказывает связь: сверяй источник/назначение и доступные идентификаторы маршрута.
- Отдельно различай `callback`: команда API сначала вызывает исходного сотрудника и после ответа — назначение. Код 1000 означает принятую команду, а не ответ получателя. Без ответа первой стороны тест назначения может не состояться.
- Для живого GraphQL-отчёта `callsHistoryRequest/Result.data` может быть списком блоков с `list`, тогда как `callsHistoryOneCallRequest/Result.data` — объект. Нормализуй форму, не считай `status=complete,data=null` доказательством отсутствия звонка. Повторяй только чтение в ограниченном окне.
- У отчётных API и АТС могут различаться часовые пояса. Сохраняй исходное время и явно установленное соответствие МСК; не определяй смещение только по локальным часам машины.

## Итог и ограничения

Сообщай время МСК, источник, назначение, кто принял, длительность, факт запуска Playback и изменения, если они были. Подтверждение записи ответа сотрудника и Playback не доказывает разборчивость или полное прослушивание; для этого нужны разрешённая проверка записи разговора либо подтверждение сотрудника. Не объявляй ответ Манго ответом человека.

В подтверждённом тесте 27.10.2026 Asterisk начал аудио в 09:18:54 МСК, а Манго показал тестового сотрудника: ожидание 2 секунды, разговор 4 секунды. Поэтому начало фразы могло обрезаться. Не повторяй этот недостаток как гарантированно рабочую полную озвучку.

Сохраняй только необходимые сведения о тесте; клиентские телефоны, пароли и токены не включай. Загрузка отдельной тестовой записи не является изменением схемы Манго. Не удаляй запись после теста без проверки, что она не используется другими настройками.

Официальные контракты: [CLI originate](https://docs.asterisk.org/Operation/Asterisk-Command-Line-Interface/Creating-and-Manipulating-Channels-from-the-CLI/), [Playback](https://docs.asterisk.org/Latest_API/API_Documentation/Dialplan_Applications/Playback/).
