# Проверенная реализация и источники

Рабочие приложения, скрипты, снимки и подключения, упомянутые ниже, задаются отдельно и не входят в публичный пакет навыка.

## Локальный прототип

Код прочитан 27.10.2026; четыре теста `node --test domain.test.mjs` прошли без подключения к рабочим системам. Корень:

`support-form (локальный прототип)`.

| Файл/точка | Подтверждённое поведение |
|---|---|
| `domain.mjs`: `services`, `validate` | Пять услуг из пользовательского скриншота; проверка и нормализация полей. Форма не принимает авторство из входного объекта. |
| `domain.mjs`: `adminPayload` | Готовит `form_uuid`, `service_uuid`, `fields[{id,value}]` только по переданному соответствию; отказывает при отсутствии обязательных полей/услуги. Не выполняет запросов. |
| `server.mjs`: `identity` | В `demo` возвращает вымышленного сотрудника; в `bitrix-preview` проверяет переданную авторизацию через `user.current` на фиксированном доверенном портале. Автор не берётся из формы. |
| `server.mjs`: `GET /api/config`, `GET /api/me` | Конфигурация возвращает `canSend:false`; профиль требует выбранного режима идентификации. |
| `server.mjs`: `POST /api/drafts` | Проверяет Origin, поля, ключ запроса; сохраняет локальный черновик SQLite с владельцем `portal:user_id`. Повтор того же ключа и содержимого возвращает прежний черновик; конфликт содержимого — 409. |
| `server.mjs`: таблица `drafts` | Уникальность `(owner, request_key)`; защита относится к локальному черновику. Транзакции создания внешней заявки и очередь сообщений отсутствуют. |
| `public/app.js`: `bitrixAuth`, `start` | Загружает SDK, вызывает `BX24.init` и `BX24.getAuth`, получает профиль через свой сервер. Поддерживает просмотр и сохранение черновика. |
| `domain.test.mjs` | Четыре проверки нормализации/подмены автора, отказов валидации, отсутствия mapping и подготовки payload. Это не проверка установленного приложения или доставки. |

Сервер слушает loopback. Режим `bitrix-preview` требует HTTPS origin, но наличие этой проверки не доказывает развёртывание reverse proxy или корректность установки приложения. В сервере нет маршрута отправки в Админ24, приёма webhook, отправки сообщения или установки приложения Битрикс. Файлы к заявке не прикладываются.

Не запускай `server.mjs` как способ «только посмотреть»: он создаёт каталог и локальную базу. `data/drafts.sqlite` содержит пользовательские черновики; не копировать в навык или публичный набор. Рабочие файлы не импортировать в другой проект без просмотра верхнеуровневых действий.

## Что остаётся неподтверждённым

- Установка приложения Битрикс и реальная идентификация на нескольких сотрудниках; обработчик установки и хранение конфигурации отсутствуют в найденном прототипе.
- Текущие UUID услуг и ID полей формы, создание заявки по реальному API, сохранение ID/UUID внешней заявки.
- Подлинность событий Админ24 и фактический формат/версия `ticket_updated` в выбранном подключении.
- Развёрнутый обработчик закрытия, outbox, доставка сообщения и защита от дублей внешних операций.
- Шкала оценки и возврат именно со стороны заявителя, поведение ссылки при повторном закрытии.

## Источники решений

Исторические чаты и параметры старого пилота не публикуются. Старое поручение с остановкой не является новым разрешением на запуск. При продолжении проверяйте действующую задачу и отдельно подтверждённую связь автора с заявкой; общая почта или совпадение телефона недостаточны.

Указатели API в README прототипа: `GET /api/form/{uuid}`, `POST /api/create-ticket`, `GET /api/ticket/by-id/{id}`, ответ создания `data.ticketId`; ссылка оценки вида `/confirm-action/rating/{ticket_uuid}`. Это исторически проверенные указатели, не полный актуальный контракт. Перед разработкой сетевой части сверить текущую документацию и ответ разрешённого чтения. Реальные UUID и состав полей в навык не включать.
