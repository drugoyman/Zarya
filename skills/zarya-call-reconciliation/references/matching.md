# Сопоставление и границы доказательств

Методика обобщена из локальных расследований; частные чаты и данные не включены.

## Нормализованная запись

Сохраняй источник и исходный ID, ключ контекста/попытки, временную зону, начало/ответ/конец, обезличенный ключ клиента, направление, сотрудника, линию/транк, исходные коды и длительности. Исходящий номер хранить отдельным полем с уровнем доказательства. Псевдонимы разных запусков нельзя объединять как один ключ без контролируемого сопоставления.

Вычисленные поля: способ связи (`shared_id`, `time_candidate`, `ambiguous`, `unmatched`), кандидаты и допуск, предыдущая попытка в оговорённой предыстории, смена АОН только если оба значения подтверждены. Нельзя подменять неизвестное значение строкой «тот же номер».

## Примеры

- В окне допуска два вызова одного клиента: обе связи неоднозначны, независимо от близости времени.
- У Манго две части и один context ID: сначала определить уровень попытки, а не считать два звонка.
- В Exolve есть cli, оператор не подтвердил подстановку каруселью: показать исходный cli отдельно, подтверждённый АОН неизвестен.
- В одном источнике 200 raw записей при UI total 1000: можно описать образец, нельзя назвать его полной историей или считать общую долю ошибок.
- После ответа 3 секунды: подтверждена зарегистрированная длительность соединения, собеседник-человек не установлен.

Сохраняй локально только необходимый объём. Не выгружай сырые клиентские телефоны в навыки, публичные репозитории или внешние чаты.
