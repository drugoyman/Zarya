# Заря: совместные тесты Talker и CallCity

Применяй для подготовки и выполнения порученных тестов, проверки повторной попытки и расследования изменения исходящего после CallCity. Для анализа истории используй также `zarya-call-reconciliation`; для назначения исходящего — `mango-staff-mobile-setup`. Озеро и аналитические БД строго только для чтения.

## Границы совместной работы

- «Изучи», «подготовь тест» и установка навыка не разрешают реальные звонки. Для прогона должны быть известны сотрудник/добавочный, наш тестовый получатель, тестовая карточка CRM, режим и число попыток. Если это уже согласовано в текущей сессии, не запрашивай повторное разрешение.
- Не звонить клиентам ради технического теста. Не менять постоянный исходящий, схемы, устройства, права и сборщики для удобства запуска. Такие изменения требуют отдельного поручения.
- Тестовую карточку готовит пользователь штатным способом: правило чтения Озера сохраняется. Запуск из CRM выполняется только в рамках явно согласованного звонка.
- При отсутствии серверного кода проверяй систему снаружи. Не обходи отказ в доступе и не представляй предположение о сервере как результат чтения исходников.

## Различай способы запуска

| Способ | Что проверяет |
|---|---|
| Кнопка CallCity в CRM | Сквозной путь выбранного режима через обработчик звонка |
| Набор в Talker / штатный `--callto` | Обычный звонок приложения; не исполнение кнопки CRM |
| Mango API callback | Отдельный API-маршрут; не сквозной тест CallCity |
| Asterisk с аудиофразой | Телефонный маршрут и воспроизведение фразы; не поведение CallCity |
| Офлайн-заглушки HTTP | Выбор параметров клиентским кодом; не работа АТС и не фактический АОН |

Перед выбором способа прочитай [references/joint-tests.md](references/joint-tests.md). Не вызывай боевые обработчики для «проверки доступности»: даже GET выбора номера может менять состояние пула.

## Прогон

1. Зафиксируй сценарий и ожидаемую линию. Прочитай текущий исходящий и контрольные поля сотрудника; сохрани безопасный снимок с ID и временем МСК.
2. Проверь версию Talker, авторизованного сотрудника и готовность приёма вызова. Зафиксируй хеш фактически загруженного кода кнопки; свежий отдельный JS не доказывает обновление кэшированной страницы или встроенного пакета.
3. Выполни ровно согласованное число попыток выбранным способом. Запиши время, режим и доступный ID запроса/коммуникации. Не запускай неоговорённый retry.
4. После каждой попытки повторно прочитай исходящий и контрольные поля. Сверь реальную линию и части вызова в Mango; для МТТ при наличии доступа сопоставь детализацию провайдера. Номер на экране получателя подтверждает получатель.
5. Отчёт: ожидание, наблюдение, снимок до/после, способ запуска, ID, подтверждённый результат и ограничения. Статусы: passed / failed / inconclusive. Принятие API-команды не доказывает звонок и ответ человека.

## Критерии остановки

Остановись при вызове нецелевому получателю, лишних попытках, изменении исходящего/других настроек, вмешательстве другого администратора или неопределённом результате. Не повторяй запуск вслепую. Возврат настроек выполняй только по отдельному либо заранее согласованному плану, с повторным чтением и защитой от чужих изменений.

Основной инвариант: CallCity может выбирать линию для конкретного вызова; после него обычный звонок должен идти по согласованной персональной настройке без её перезаписи. Конкретный транк, маршрут повторной попытки и правила УД берутся из текущего задания, не назначаются по историческому примеру.

## Доступы и артефакты

Секреты загружай из разрешённого локального подключения только в память. Не сохраняй SIP-пароли, токены, сессии, полные HAR и клиентские телефоны в навык или Git. Рабочий код CRM/сервиса не копируй в публичный навык. Для истории назначений не подменяй прежнюю настройку номером из прошлого звонка; SIP мог переиспользоваться другим сотрудником.
