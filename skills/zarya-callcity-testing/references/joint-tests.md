# Сценарии и технические ориентиры

## Talker

Штатный запуск Windows по документации: `mango-talker.exe --callto=<согласованный тестовый номер>`. Сначала найди реальный исполняемый файл, проверь версию и текущую авторизацию. Не запускай `--callto`, включая «проверку параметров», без согласованного тестового вызова. Местоположение и версия могут меняться; фиксированный путь чужого компьютера не использовать.

## Историческая ошибка CallCity — ориентир для регрессии

В прочитанном снимке 27.10.2026 условие `algorithm == 520` без проверки режима перезаписывало `operator` на `mtt_sip`, включая обычный режим `default`. В статическом файле, проверенном 28.10.2026, оно уже ограничено `fields.callMode == 'call_city'`. Это историческое наблюдение, не гарантия актуальной выкладки.

Клиент отправлял в `manual_call`: `city_crm_id`, `lead_crm_id`, `user_crm_id`, `number`, `outgoing_number`, `operator`. `callMode` и номер попытки отдельно не передавались. Проверяй текущий контракт заново; не выводи из этих полей автоматически число попыток или правило резервирования.

Выбор режима дополнительно сохранялся через `update_active_number`; это запись. `get_logic_v2_btn_call` вызывался даже для режимов default/ud, а его серверные побочные эффекты не установлены. Нельзя считать любой GET диагностическим чтением.

Пользователь сообщил о серверной ошибке кнопки, заменявшей постоянный исходящий на транк. Серверный код в этой проверке не был доступен; точный оператор записи не установлен чтением фронтенда. Для доказательства нужны разрешённые серверные трассировки или воспроизводимый согласованный тест с read-back.

## Матрица проверок

| Сценарий | Ожидание |
|---|---|
| Обычный звонок до CallCity | Согласованная персональная линия |
| CallCity при целевом алгоритме | Выбранный для этого сценария транк только в данном вызове |
| CallCity → обычный повтор | Линия согласно заданию; постоянный исходящий не перезаписан |
| Красивый номер УД | Утверждённый номер без изменения профиля |
| Иной город / алгоритм | Правильная ветвь и актуальный маппинг |
| Занято / нет ответа / сброс | Нет лишнего запуска; согласованная логика повторной попытки |
| Обновление / новая вкладка | Режим понятен, кэшированная старая логика исключена |
| Второй сотрудник | Нет влияния первого теста на его настройки; сначала последовательные прогоны |

Сначала проверяй маршрутизацию на офлайн-заглушках: целевой/нецелевой алгоритм × default/call_city/ud. Запрети реальные HTTP-вызовы в стенде. Затем выполняй только согласованный живой сценарий. Не используй успешные офлайн-тесты как доказательство отсутствия записи в профиле на сервере.

## Запись результата

`Время МСК | сотрудник/добавочный | тестовая карточка | режим | ожидаемая линия | фактическая линия и источник | исходящий до/после | ID запроса/коммуникации | завершение | passed/failed/inconclusive`.

Разделяй API status, регистрацию попытки, ответ АТС, запуск аудио, разговор с человеком и АОН на экране. Не считать соединение разговором и не трактовать коды Mango как SIP без подтверждения. Критический stop и запрет слепых повторов действуют также при таймауте.
