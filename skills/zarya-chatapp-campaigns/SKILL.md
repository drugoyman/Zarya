# Заря: рассылки ChatApp

## Режим и доступ

Различай проверку, подготовку и отправку. «Подготовь», «проверь», «покажи план» разрешают чтение и локальные материалы, но не сообщения адресатам. Выполняй уже явно порученную отправку без повторного согласования, если известны текст/вложение, состав получателей, каналы, охват и условия запуска. Уточняй только недостающие существенные решения.

Доступы загружай непосредственно из существующего разрешённого источника. Для локальной Зари сначала прочитай локальную инструкцию доступа проекта; не копируй секреты в навык, команды, журналы и ответы. Облачный чат не получает эти файлы автоматически.

Для чтения лидов используй `zarya-crm-semantic-layer`: Озеро / sitemanager строго READ ONLY, без изменения карточек, процессов, открытых линий и настроек. Наличие ChatApp API не разрешает конфигурационные изменения, подключение линий или создание расписания.

## Подготовка

1. Установи кампанию и её отличие от прошлых запусков: источник списка, дату среза, текст, вложения, допустимые каналы/линии, период Europe/Moscow, объём и условия остановки. Предыдущие номера, окна, интервалы и лимиты не являются значениями по умолчанию.
2. Прочитай [references/operations.md](references/operations.md) перед выбором клиента или продолжением запуска. Проверь текущий аккаунт, полный каталог лицензий и состояний мессенджеров; оплаченная лицензия не доказывает работоспособность канала.
3. Нормализуй телефоны с проверкой страны и длины, не превращай произвольное значение в российский номер отсечением последних цифр. Сохрани связь исходной строки, клиента и лида. Удали повторы в рамках согласованной единицы отправки; учти прежние отправки, отказы и исключения текущей кампании.
4. Различай отсутствие пользователя в мессенджере, ошибку проверки, отключённый канал и неизвестный результат. Переход в другой канал выполнять только по согласованному правилу; ошибка не является разрешением написать второй раз.
5. Подготовь сверяемый предварительный итог: строк исходника, валидных уникальных адресатов, исключений по причинам, доступных линий, готовых сообщений. Проверь согласованность текста и вложения. Вариации текста допустимы только в пределах поручения, без изменения предложения клиенту.

## Отправка и продолжение

- Веди локальный журнал до первого запроса. Для каждой попытки сохрани кампанию, псевдоним получателя и защищённую связь с исходником, канал/линию, время, версию текста/вложения, идентификатор попытки, прикладной ответ, серверный ID сообщения и результат последующей проверки.
- Перед отправкой повторно проверь остановку, разрешённое окно и доступность линии. Обеспечь одного исполнителя кампании: второй процесс не должен читать ту же очередь как свободную.
- Запиши состояние `sending` до сетевого запроса. HTTP 200 не равен успешной отправке; даже прикладное принятие API не доказывает доставку или прочтение.
- При таймауте/обрыве после начала запроса оставь `unknown`/неопределённую попытку, останови дальнейшую отправку и проверь историю/серверный ID. Не возвращай её в очередь автоматически. Клиентский tracking ID сам по себе не доказывает идемпотентность API.
- Для подтверждённого отказа зафиксируй причину и соблюдай условия кампании. Не обходи отказ другой линией, аккаунтом или каналом без соответствующего разрешения. Ограничение скорости не устраняй увеличением параллелизма.
- При «продолжай» сначала проверь журнал, живую историю, число активных исполнителей и актуальность поручения. Отправляй только ещё не обработанных адресатов; неопределённые попытки сначала разреши чтением. Не снимай ранее поставленную пользователем остановку без поручения возобновить.
- Смена текста, приложения, адресатов или охвата требует проверки, что новое действие входит в поручение. Сообщай частичный результат, если часть кампании выполнена.

## Проверка и ответ

Сверь исходный состав с журналом: исключённые, ожидающие, принятые API, подтверждённо доставленные, прочитанные, отказы и неопределённые. Эти показатели могут быть вложенными состояниями, поэтому не складывай их как независимые группы без нормализации последнего состояния попытки.

Дай время МСК и короткий итог с границей доказательств. Клиентские номера и тексты ответов не включай в общий отчёт без необходимости; подробный журнал храни локально. Для сравнения влияния на лиды переходи к `zarya-campaign-results`, сохраняя фактический состав и моменты отправки.
