# Анкета КЦ Зари

Используй для объяснения, проверки и проектирования переноса анкеты первичного разговора в Битрикс24. Навык сохраняет статически восстановленную логику Excel версии 09.09.2025, а не утверждённые юридические критерии или готовую интеграцию.

## Источник и границы

- Перед выводами прочитай [разбор формул](references/excel-logic.md). Для другой версии файла повторно проверь формулы, ссылки элементов управления, примечания и VBA; прежний разбор не доказывает её поведение.
- Исходный XLSM не включён. Если его нет, отвечай по сохранённому разбору с указанием версии и границ статической проверки. Не заявляй, что открыл или пересчитал файл.
- Анкета собирает данные, независимо рассчитывает БФЛ, реструктуризацию и ВБФЛ, выводит качество и целевой статус, формирует подсказки и текстовую сводку. Правил ВКИ и КУЗ в этой версии нет.
- «Качественный» и «целевой» — разные результаты. Несколько направлений могут подходить одновременно; приоритет не задан.
- Не считай константы 19 329 / 17 201 и пороги долга актуальными нормами. Для проверки актуальности используй действующие официальные источники; для изменения бизнес-правил нужно согласование методологии.
- Озеро / sitemanager остаётся только для чтения. Этот навык не разрешает менять CRM, роботов, записи или права и не содержит подключений. Для порученного внедрения сначала проверь применимые ограничения и доступы; не обходи запрет через UI/API.

## Работа с анкетой

1. Определи режим: объяснение текущего файла, аудит расхождений или проектирование интеграции. Сохраняй порядок вопросов пользователя.
2. Разделяй введённый факт, расчёт, текст подсказки и подтверждённое менеджером решение. Не подменяй отсутствие ответа нулём или «нет».
3. Проследи расчёты до исходных ответов. VBA этой версии обслуживает копирование/очистку; бизнес-формулы находятся в ячейках. Не запускай макросы ради чтения.
4. Объясняй срабатывающие и блокирующие условия, включая особую ветку целевого статуса, которая обходит критерии G, когда БФЛ не подходит, а другое направление подходит.
5. Отмечай как расхождения реализации: неполноту вывода подсказок, отсутствие проверки достаточности ответов, различие экранного и копируемого вердикта. Не превращай их в новые согласованные правила.

## Подготовка переноса

Построй карту «вопрос → ответ → условие → результат → подсказка → поле CRM». Сначала проверь существующие поля и справочники нужной сущности, не создавай дубли по названиям. Лид — первоначальное предположение для КЦ, не универсальное требование.

До реализации согласуй определения качества/целевого статуса, спорные ветки, актуальные параметры, достаточность данных и выбор при нескольких услугах. Перенос одних полей не воспроизводит Excel. Не придумывай правила ВКИ/КУЗ.

Для новой реализации предложи: ответы → достаточность данных → объяснимые правила → подсказки → подтверждение менеджером → сохранение. Проверяй неполные ответы, граничные суммы, разные направления и совпадение сводки с экраном. Отделяй проектируемое поведение от фактически работающего.
