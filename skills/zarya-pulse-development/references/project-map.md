# Точки интеграции Пульса

Внутренние пути и развёртывание задаются локально. Этот репозиторий не содержит исходники Пульса, рабочие БД или файлы доступа. Перед изменением найдите актуальные рабочие исходники, существующий Git-репозиторий/снимок и инструкции проекта.

Проверенные ориентиры в приложении, которые нужно перепроверять в текущем коде:

- accounts.py: SECTIONS, setup(), allowed(), authorize(), home(); home() содержит список самостоятельных стартовых путей.
- app.py: protect() для сессии/CSRF, crm_query() для чтения CRM, register_plan_fact(app,state,audit) для подключения План / Факт.
- plan_fact.py: /plan-fact, /api/plan-fact, /api/plan-fact/plans; сохранение проверяет g.can_write.
- templates/accounts.html и templates/plan_fact.html — пользовательские права и форма.
- test_accounts.py, test_plan_fact.py, test_plan_fact_permissions.py — ориентиры существующих проверок, если они есть в выбранной версии приложения.

Эти файлы не поставляются вместе с навыком. Наличие имени функции не доказывает авторизацию нового маршрута; проверьте каждый путь фактически.

Требования пользователя: планы вводятся в Пульсе, факты читаются из Озера; каждый новый раздел добавляется в управление правами пользователей. Каталог CRM — датированный локальный материал; проверяйте таблицу, ENTITY_ID и enum через разрешённое чтение.
