# Проверки по затронутой логике

Выбирай существенные сценарии для изменения, не создавай тесты ради совпадения текста или структуры реализации.

## Новый раздел и права

- Новый пользователь без флажка: нет пункта меню; прямой URL страницы и каждый API не отдают данные.
- Есть доступ к разделу, нет права изменений: чтение разрешено, изменение плана запрещено сервером.
- Отозванный доступ и старая сессия: сервер проверяет актуальные права по действующему механизму приложения.
- Существующие пользователи не получили новый доступ автоматически.
- Стартовая страница недоступна: выбирается реально разрешённая; при отсутствии доступов данные не раскрываются.

## План / Факт

- Пустые планы остаются незаданными, явный ноль сохраняется нулём.
- Одна из составляющих отсутствует: итог не изображает полный суммарный план.
- Конец месяца и закрытый период: корректный остаток дней, нет деления на ноль.
- Повторное редактирование: конфликт версий не затирает чужой план, аудит сохраняет действие.
- Ошибка или неполная реплика: отчёт сообщает ограничение, не превращает его в нулевой факт.

Равенство общего числа таблице аналитиков не доказывает равенство состава. При спорной сверке сравнивай множества ID и причины расхождений: текущие регион/услуга/стадия могли измениться после старого отчёта.
