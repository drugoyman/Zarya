# Заря: города и пулы номеров

Используй `zarya-crm-semantic-layer` для источников и смысла полей. Озеро строго только чтение, включая справочники, варианты перечислений и изменения через UI/API. Историческая замена номеров в чатах не даёт разрешения повторять запись. Задача сверки не разрешает закупку, подключение или смену телефонии.

Сначала прочитай локальную инструкцию доступа проекта; используй существующее разрешённое подключение без вывода секретов. Сами файлы доступов, клиентские телефоны и сырой каталог не включать в публичные материалы.

## Определить задачу

Различай: поставка оператора, наличие номера в телефонном справочнике, привязка к городу, текущая конфигурация алгоритма, фактический исходящий АОН. Если пользователь просит только новые привязки из «Неопознанных городов», перейди к `zarya-unrecognized-cities` и его короткому формату.

Проверка рабочих привязок города не является подбором ближайшего офиса. Географический регион, макрорегион Север/Юг, активность записи, открытие офиса и обслуживаемая территория — разные признаки.

## Сверка

1. Зафиксируй источник/версию поставки, листы и диапазоны, дату среза, ограничения задачи и единицу учёта. Сверь полноту входных строк, включая дубли/пустые и листы вне видимой области. Прежнее число городов/номеров не является вечным составом.
2. Сохрани исходные значения. Нормализуй номера с проверкой страны, длины и допустимого формата, сохраняя связь со строкой. Не отсекай последние цифры ради совпадения, не теряй добавочные и не смешивай их с номером. Объём строк и число уникальных нормализованных номеров считай отдельно.
3. Сопоставь города по проверенным ID/справочнику, названию и географическому региону. Латинские названия и алиасы подтверждай явно; одноимённые города не объединяй. Сортировка итоговой проверки не должна скрывать исходный порядок и строки с неразрешённой привязкой.
4. Прочитай актуальный справочник городов и телефонный каталог полностью в согласованном объёме, с проверкой пагинации/лимита. В параметризованных SELECT используй read-only транзакцию, таймаут и rollback. Активность и значение поля «офис открыт» проверяй отдельно; пусто не равно «нет».
5. Разверни множественные привязки и сопоставь через их настоящий тип ключа. В разных местах могут быть ID записи номера, ID варианта перечисления, текст телефона, API ID линии или ссылка на город — они не взаимозаменяемы.
6. Сравни множества по каждому городу и отдельно по всему каталогу: пересечение поставки с привязкой, поставка без привязки, привязка вне поставки, поставка без записи в каталоге. Отдельно отметь дубли между городами, неразрешённые ссылки, неактивные записи и неизвестные статусы.

Проверенные ориентиры и пример расчёта: [references/reconciliation.md](references/reconciliation.md). Корпоративные номера можно включать в необходимую локальную таблицу сверки; клиентские контакты и токены в отчёт не добавляй.

## Проверка телефонии и план

Наличие номера в поставке, подпись, правильный код или привязка CRM не доказывают активность линии, работу алгоритма либо АОН на конкретном вызове. Для фактических попыток используй `zarya-call-reconciliation`; значение cli считай подтверждённым только после проверки его семантики. Префикс сам по себе не устанавливает текущего оператора мобильного номера.

Для изменения красивых номеров подготовь план по существующим ID и зависимостям: переименование текста варианта, изменение выбранного варианта у города и добавление новой записи имеют разные последствия. ID используемых вариантов сохранять в проекте плана; не удалять и не пересоздавать их как способ переименования. Не применять план в Озере, даже через другую форму/API. Для другой системы выполнение требует соответствующего текущего поручения.

## Результат

Таблица: исходный город и его ID, географический регион, макрорегион, активность/офис, поставка (строки и уникальные), каталог, привязки, пересечение и различия, неизвестные связи, рекомендация. Сохраняй исходный порядок, если иной не задан, и покажи общие итоги без двойного счёта многократно привязанных номеров. При неполном каталоге не заявляй отсутствие номера или полный объём расхождений. Разделяй предложение и выполненное изменение.
