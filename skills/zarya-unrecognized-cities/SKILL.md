# Заря: привязки неопознанных городов

## Что требуется пользователю

В списке №268 заполняется поле **«К какому городу привязать»** значением города из справочника №54. Номер телефона не является значением этого поля. Наличие региональной телефонии помогает обосновать выбор города, но не подменяет итоговую таблицу телефонией.

Используй также `zarya-crm-semantic-layer`: источник CRM «Озеро» / `sitemanager` строго только для чтения. Для источников, проверенных идентификаторов и исторического примера прочитай [references/access-and-example.md](references/access-and-example.md).

Перед подключением прочитай локальную инструкцию доступа проекта и используй существующий источник доступа без вывода секретов. Наличие доступа не разрешает заполнение списка.

## Подбор

1. Прочитай актуальный список №268 полностью, проверь количество строк и пагинацию/ограничения выборки. Получи актуальный справочник №54 с ID и активностью. Не используй фиксированный перечень восьми городов как вечный состав списка.
2. Уточни исходный населённый пункт и его регион. Не объединяй одноимённые города. Пользователь подтвердил: **Донецк в исходном примере — Донецк в ДНР, не в Ростовской области**. Для новых неоднозначных строк уточняй отдельно.
3. В первую очередь ищи действующий город справочника в том же регионе. Если задача включает наши номера, проверь их существование и регион по свежему каталогу; подпись офиса не доказывает географию номера, а мобильный префикс не подтверждает текущего оператора или регион без дополнительной проверки.
4. Если подходящего города того же региона нет, подбери ближайший допустимый город справочника и зафиксируй различие регионов в рабочей проверке. В стандартный короткий ответ третий столбец и пояснение не добавляй; показывай их только по отдельному запросу обоснования. Когда разрешены только совпадения региона, не подставляй соседний регион: укажи отсутствие подходящей привязки либо уточни существенную неоднозначность.
5. Для телефонного сопоставления по умолчанию сравнивай географическую близость **по прямой**. Проверяй координаты/расстояния по источникам и близкие альтернативы; не называй вариант абсолютно ближайшим, если проверена лишь часть справочника. Не смешивай прямое расстояние с автомобильным маршрутом и не делай вывод о доступности поездки по географической близости.
6. Выбирай реальные активные города, не виртуальные записи «Россия», «Удалённый формат», названия подразделений или неактивные региональные заглушки. Регион — отдельный субъект/область: ЯНАО не ХМАО, ЕАО не Хабаровский край, Тыва не Хакасия, Северная Осетия не Чечня. Не отождествляй географический регион с внутренним макрорегионом продаж Север/Юг.
7. Если нужно учитывать Север/Юг, проверь фактическую принадлежность в CRM; не выводи её из положения города на карте. Не меняй фактический город клиента, ответственного, офис обслуживания или маршруты звонков вслед за предложением привязки.

## Итог

По умолчанию возвращай **только новые строки, у которых поле привязки сейчас не заполнено**, строго в порядке актуального исходного списка №268. «Новые» здесь не означает дату создания или отсутствие в прошлой переписке: отбор определяется текущим пустым полем, а не памятью о предыдущем ответе.

Формат — одна пара на строку:

```text
Исходный город → Город привязки
```

- Не включай ранее заполненные строки, даже с пометкой «оставить». Не сортируй по алфавиту, расстоянию или макрорегиону. Не объединяй разные исходные строки из-за одинакового названия.
- Без отдельного запроса не добавляй заголовок, таблицу, нумерацию, ID, телефоны, расстояния, регионы, время проверки, объяснения и фразу о том, что запись не выполнена. Это предложения; фактическое заполнение не заявляй.
- Перед ответом проверь, что прочитан весь источник и каждой незаполненной строке соответствует результат в том же порядке. Заполненные строки нужны для проверки источника, но не для выдачи.
- Если новых незаполненных строк нет, кратко сообщи: «Новых непривязанных городов нет».
- Если источник недоступен/неполон, не выдавай прежний пример за актуальный полный список: кратко сообщи ограничение. Если населённый пункт неоднозначен, уточни его; не придумывай выбор ради короткого формата. При отсутствии допустимого варианта допустимо «Исходный город → нет подходящей привязки».
- Полную таблицу, заполненные строки и обоснования показывай только когда пользователь отдельно просит именно их; ограничения чтения сохраняются.

## Границы

«Проверь», «подбери», «предложи» — только чтение. Не записывай в CRM/списки, не запускай БП или PHP, не меняй Mango/Скорозвон, права и настройки. Не создавай расписания без отдельного запроса. Навык не предоставляет разрешения на запись. Если пользователь отдельно просит применить изменения, сначала согласуй конкретную таблицу и соблюди ограничения `zarya-crm-semantic-layer`; не обходи запрет записи в Озеро через UI/API.

Старый список №267 **не является эталоном**: его потребители и назначение привязок не подтверждены. Не копируй его значения автоматически.
