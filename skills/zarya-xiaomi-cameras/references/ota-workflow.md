# Очередь OTA и доказательства результата

Это методика для существующей разрешённой интеграции. Backend, доступы, журнал устройств и рабочие скрипты не входят в пакет навыка.

## До команды

На выбранную камеру сохрани в защищённом локальном журнале: внутренний ключ устройства, модель, аккаунт/регион, исходную установленную версию и источник/время, предложенную целевую версию, состояние online, ID задания, согласованный состав и параллельность. В общий отчёт выводи только необходимое название города/комнаты и версию, без чувствительных идентификаторов.

Проверь, не идёт ли уже установка/доставка команды и не осталась ли неопределённая попытка после прежнего сбоя. Наличие доступного места в очереди не разрешает повторить ту же попытку. Перед непосредственным OTA запуском повторно проверь условия: версия могла обновиться вручную, камера — уйти офлайн, очередь — измениться другим оператором.

Доступное обновление должно быть предложено Xiaomi именно данному устройству по проверенному контракту. Состав, модель и plugin level проверять по текущему коду/метаданным, не по APK другой версии и не по одной похожей строке модели. Пакет не скачивать и не передавать камере самостоятельно, если пользователь поручил штатную установку через сервис.

## После команды

| Наблюдение | Допустимый вывод |
|---|---|
| HTTP-успех и прикладное принятие | Команда принята; установка ещё не подтверждена |
| Сетевой таймаут после отправки | Исход команды неизвестен; читать журнал/OTA и версии, не повторять автоматически |
| Downloading / installing / downloaded | Подтверждена соответствующая стадия; версия ещё может остаться старой |
| Прогресс 100% | Сам по себе не подтверждает установленную целевую версию |
| Idle и старая версия | Установка не подтверждена; действовать по текущему grace period и правилам job, не менять их по старому примеру |
| Облако показывает цель, свежий ответ камеры — старую версию | Противоречие, успех пока не подтверждён |
| Свежие согласованные версии цели и камера в сети | Успех подтверждён на момент проверки при проверенной семантике полей |
| Только прежняя версия из облака, камера офлайн | Последнее известное состояние с датой; свежая установленная версия не проверена |
| Job completed_with_problems | Завершён обход очереди с проблемами; не все камеры успешно обновлены |

При ошибке приложение может остановить очередь или пропустить проблемное устройство по специально согласованному правилу. Проверь актуальную реализацию и состояние job; не объявляй любое продолжение ошибкой и не продолжай сам там, где очередь остановилась. Сбой наблюдения и явный отказ установки различай.

Перезапуск процесса, новая авторизация и обновление страницы не должны быть способом повторной отправки OTA. Сначала разберись с восстановлением persistent job. Остановленная очередь не гарантирует остановку уже принятой камерой команды; не отключай питание во время возможной установки.

## Проверочные примеры

- Каталог: A онлайн и актуальна, B офлайн и ранее подтверждённо актуальна, C онлайн и отстаёт, D статус/версии неизвестны. Всего четыре; онлайн две, офлайн одна, неизвестна одна. Последние подтверждённые актуальные — A и B с разной свежестью; неизвестную D нельзя объявить обновлённой или офлайн.
- Прежний offline-список содержал B и C; сейчас B онлайн, C неизвестна, новый D онлайн. «Появилась из прежнего офлайна» только B; D — новое устройство, C — не проверена.
- Пользователь разрешил две параллельные установки, в очереди уже есть одна неопределённая активная попытка. Не начинай две дополнительные, пока не установлены фактические активные слоты и правила восстановления.
- Пользователь просит отчёт по всем камерам, сервис вернул только прежнюю проблемную партию. Отчёт ограничить партией, общий итог аккаунта не заявлять.
